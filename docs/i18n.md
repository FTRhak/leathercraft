# Localization (`i18n`)

How user-facing text is translated. The module lives in the library crate, in `src/i18n/`, so core code can return translatable errors without depending on the UI. The binary picks the language and renders the text.

| File | Contents |
|---|---|
| `src/i18n/mod.rs` | `Language`, `Label`, `Message`, tests |
| `src/i18n/en.rs` | English catalog |
| `src/i18n/uk.rs` | Ukrainian catalog, plus `plural` and `decimal` helpers |

Supported languages: English (`en`, the default) and Ukrainian (`uk`).

## The three types

| Type | What it is | Render with |
|---|---|---|
| `Language` | The current interface language | — |
| `Label` | Fixed text with no arguments: menu items, button names, tooltips, field names, enum values | `language.label(Label::X)` → `&'static str` |
| `Message` | Text with arguments, or text that is stored and shown later: status line, errors, history entries | `language.message(&Message::X { .. })` → `String` |

`language.unit_symbol(units)` gives the translated symbol for `Units` (`mm`/`мм`, `in`/`дюйм`).

### Choosing between `Label` and `Message`

- Text that never changes and is drawn on the spot → `Label`.
- Text with a number, name or path in it → `Message`.
- Text that is created in one place and shown later, such as a status or error → `Message`, even with no arguments (`Message::Ready`, `Message::PieceDeleted`). It stays structured until it is drawn, so switching the language re-renders it.
- Values of an enum (material properties, boolean operations) → a `Label` variant that wraps the enum, such as `Label::Operation(BooleanOp)` or `Label::Color(LeatherColor)`. The catalog matches on the inner value in a helper function.

## Rules

- **All user-facing text goes through `i18n`.** No string literals in `ui.label`, `ui.button`, tooltips, dialog titles or file-dialog filters.
- **Log messages stay in English** and don't use `i18n`.
- **Keep `Message`, not `String`, as long as possible.** Store `Message` in state (`EditorState.status` is a `Message`) and call `language.message` only when drawing. A pre-rendered `String` would not follow a language change.
- **The language is interface state.** It lives in `EditorState.language` and is saved by `settings`, never in `Project` or a `.leathercraft` file.
- **Catalogs are exhaustive `match`es** with no wildcard arm, so a variant missing from any language is a compile error. Never add a `_ =>` arm.
- **`detail` arguments are not translated.** They carry text from the OS or serde (`CouldNotRead { path, detail }`) and are inserted as is.

## Using it in the binary

Get the language from `EditorState` and render at draw time:

```rust
let language = state.language;
if ui.button(language.label(Label::ZoomToFit)).clicked() { /* … */ }
ui.colored_label(ui.visuals().error_fg_color, language.message(&error));
ui.label(format!("{} {}", value, language.unit_symbol(units)));
```

Icon buttons take a translated label as their tooltip and accessible name; see `docs/icons.md`:

```rust
icon_button(ui, ICON_BUTTON_SIZE, false, language.label(Label::DeletePiece), paint_trash)
```

Status and errors go through `EditorState::report` and `report_error`, which take a `Message`:

```rust
state.report(Message::Saved { path: path.display().to_string() });
state.report_error(error); // error: Message, from a library call
```

## Using it in the library

Functions in `model`, `events` and `persistence` return `Result<_, i18n::Message>`:

```rust
return Err(Message::PieceLocked { name: piece.name.clone() });
```

`exports` returns `ExportError`, which converts with `From<ExportError> for Message`, so the UI can use `?` or `.into()` and render it the same way.

`Message` implements `Display` (always English) and `std::error::Error`. Use `Display` only for logs and tests, never for the UI.

History entries are `Message::Action…` variants returned by `History::describe`. `Undone`, `Redone` and `HistoryRestored` wrap one in a `Box<Message>` and render it inside their own text.

## Language selection

At startup, `settings::load_language` picks the language in this order:

1. The language saved in the settings file, if the user chose one.
2. The OS locale from `sys-locale`, through `Language::from_tag`.
3. `Language::default()`, which is English.

`Language::from_tag` matches only the primary subtag, case-insensitively, so `uk-UA`, `UK_ua` and `uk` all give Ukrainian. Unknown tags give `None`.

The language picker in the bottom bar (`editor/ui.rs`, `language_control`) shows each `Language::native_name` and, on a change:

- sets `state.language`,
- saves it with `settings::save_language`,
- calls `PanelDock::set_language`, because `egui_dock` caches its own button texts (close, float) and doesn't read them each frame.

Everything else re-renders on the next frame. Other UI that caches translated text needs the same kind of update.

## Adding text

### A new label

1. Add a variant to `Label` in `mod.rs`, near related ones. Add a `///` comment if the name doesn't make the text obvious.
2. Add an arm to `label` in `en.rs` and `uk.rs`.
3. Use it: `language.label(Label::NewThing)`.

### A new message

1. Add a variant to `Message`, with named fields for its arguments: `TooManyChildren { name: String, max: usize }`.
2. Add an arm to `message` in `en.rs` and `uk.rs`, built with `format!`. Variants without arguments return `"…".to_owned()`.
3. Return it from library code or pass it to `report`/`report_error`.

### A new enum value

For a new value of a translated enum, such as a `LeatherColor`, add an arm to its helper function (`color`, `texture`, …) in both catalogs. For a new translated enum, add a `Label` variant that wraps it, plus a helper function in each catalog.

The compiler lists every missing arm, so `cargo check --lib --no-default-features` is enough to find them.

### Writing the translations

- **Punctuation:** messages for the status line are full sentences with a final period; labels and history entries have none. Menu items that open a dialog end with `…`.
- **Quotes:** English uses `'name'`, Ukrainian uses `«name»`.
- **Numbers:** English uses `.` as the decimal separator; Ukrainian uses `,` through `decimal(value)` in `uk.rs`. Integers need no helper.
- **Plurals:** Ukrainian has three forms. Use `plural(count, one, few, many)` in `uk.rs`, as `PointCount` does (`1 точка`, `2 точки`, `5 точок`, `11 точок`, `21 точка`). English matches the singular as a separate arm, such as `Message::PointCount { count: 1 }`.
- **Units:** use `unit_symbol` rather than writing `mm` into a translation, except in fixed limits such as thickness, which are always millimeters.
- Keep labels short enough for their widget; Ukrainian text often runs 20–40% longer than English.

## Adding a language

1. Add a variant to `Language` and to `Language::ALL` (update its length).
2. Add arms to `tag` (the ISO 639-1 code), `native_name`, `label`, `message` and `unit_symbol`.
3. Create `src/i18n/<tag>.rs` with `pub(super) fn label`, `pub(super) fn message` and `pub(super) fn unit_symbol`, plus its helper functions, and declare it with `mod <tag>;` in `mod.rs`. Copying `en.rs` and translating it is the quickest start.
4. Add the language's own plural and number rules as local helpers in its catalog, like `plural` and `decimal` in `uk.rs`.
5. Extend the tests: `language_tags_round_trip` covers the new tag automatically; add cases for its OS locales, plurals and decimal separator.

`from_tag` and the language picker use `Language::ALL`, so they need no change.

## Tests

The `i18n` tests in `mod.rs` cover tag round trips, OS locale matching, Ukrainian plurals, decimal separators, and that `Display` is English while `Language::message` renders the chosen language. Run them with:

```sh
cargo test --lib --no-default-features i18n
```

Add a test when a translation has logic in it (plurals, number formatting, nested messages), not for plain strings.

## Checklist for new text

- [ ] No user-facing string literal outside `src/i18n/`.
- [ ] `Label` for fixed text, `Message` for text with arguments or text shown later.
- [ ] Arms added to every catalog; no wildcard arm.
- [ ] Stored as `Message`, rendered with `language.message` at draw time.
- [ ] Ukrainian uses `«»`, `decimal` and `plural` where they apply.
- [ ] Any UI that caches translated text is refreshed on a language change.
